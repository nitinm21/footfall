## Overview

Footfall is agent-experience analytics: "Google Analytics + Hotjar, except the visitor is Claude Code." Site owners are blind to the AI agents that now make up a large share of their traffic; Footfall classifies agent traffic behaviorally, reconstructs sessions, surfaces where agents fail (404s, auth walls, empty JS shells, retry loops), and generates fixes (llms.txt, markdown mirrors, redirects) from observed demand — then measures whether the fix worked.

**v1 strategy (locked in prior sessions):**
- **The wedge is a log/capture-based static report** — zero-trust ask, no infra needed by the site owner, generated by a pure pipeline.
- **The product is the live snippet + dashboard** — observe-only middleware, always-on, free.
- **No "Agent Success Score."** Only countable outcomes (status codes, detectable patterns). Heuristic metrics are shown but always flagged `HEURISTIC`. Honest `unclassified` bucket, never force-assigned.
- **Classification receipts everywhere** — if we can't show the signals, we don't show a family. This is the trust feature.
- **Free product.** No billing, no plans, no orgs. Multi-tenant *minimum* only: site tokens, login, isolation, caps.
- **Primary goal is the hiring artifact**; the plan ends with the launch data post. Business scaffolding is out of scope.

## Locked Decisions

| Decision | Choice | Why |
|---|---|---|
| First platform | Vercel / Next.js | Own sites dogfood there; simplest adapter; natural recruit pool |
| Event store | Tinybird (managed ClickHouse) | Least ops for a solo builder; hosted query API; free tier |
| App metadata store | Neon Postgres (or Vercel Postgres) | Users/sites/tokens are OLTP, not analytics; boring and free |
| Language / runtime | TypeScript everywhere, Node 22, pnpm workspaces | One language across middleware, pipeline, web |
| Web framework | Next.js (App Router) on Vercel | Dashboard + ingest API + docs in one deploy |
| Auth | Auth.js with GitHub OAuth | Target users are developers; no password/email infra |
| Lint/format | Biome | Single fast tool; less config for agents to fight |
| Tests | Vitest (unit/golden), `@playwright/test` (UI), autocannon (load) | Deterministic, CI-runnable, agent-drivable via Bash |
| CI | GitHub Actions | typecheck + lint + tests + accuracy gate on every push |
| Email (digest/alerts) | Resend | Phase 6 only |
| Session definition | same (site, ip_hash, ua_fingerprint), gap < 15 min | Simple, defensible v1 |
| IP handling | salted hash, salt rotates daily; raw IP never stored | Session stitching without PII retention |
| Event cap | per-site daily cap with graceful sampling above it; drops are counted and visible | Protects the free tier's bill; no silent truncation |
| Classifier posture | Tier 1 UA-exact → Tier 2 browser heuristics → Tier 3 behavioral agent → `unclassified` | Precision over coverage; accuracy published, never guessed |
| Failure taxonomy (v1) | `dead_end` (404/410) · `auth_wall` (401/403) · `empty_shell` (heuristic) · `retry_loop` | All countable or explicitly flagged heuristic |
| Report ⇄ dashboard parity | aggregations defined once in `packages/core`; Tinybird pipes mirror them; parity test enforces equality | Prevents the two surfaces from drifting |

### Event schema v1 (the single contract)

Both the log parsers and the middleware normalize into this shape; everything downstream consumes only this.

| Field | Type | Notes |
|---|---|---|
| `v` | int | event schema version (1) |
| `ts` | int64 ms | edge/log timestamp |
| `site` | string | site token |
| `method` | string | |
| `path` | string | query string dropped; a `has_query` bool kept |
| `has_query` | bool | whether the request carried a query string (string itself dropped) |
| `status` | int \| null | **null when the source can't observe it** (Next middleware pre-render; assets/API routes without beacons) — nullable per the coverage-matrix design; resolved in Phase 0 |
| `resp_bytes` | int \| null | null when the source can't provide it |
| `content_type` | string \| null | |
| `duration_ms` | int \| null | |
| `ua` | string \| null | verbatim; **absence is itself a signal** |
| `accept` | string \| null | markdown-preference feature |
| `sec_fetch_mode` | string \| null | browser fingerprint feature |
| `referer_host` | string \| null | host only |
| `conditional` | bool | If-None-Match / If-Modified-Since present |
| `ip_hash` | string | salted (daily rotation), never raw |
| `asset` | bool | css/js/img/font — **kept, not dropped**: asset ratio is a top classifier feature |

Nullable fields power the **field-coverage matrix**: a report module whose required fields are null for the source greys out; it never breaks and never silently shows wrong numbers.

> **Phase 4.5 adds `bot_verified` (`verified` \| `spoofed` \| null).** User-agent strings are spoofable — observed live: Cursor impersonates Googlebot — so self-declared crawler/agent claims are verified against operator IP ranges before being trusted.

### Data flow

```
Vercel log drain ─┐
uploaded JSONL  ──┼─> normalize -> Event[] ─┬─> core pipeline (classify -> sessionize -> detect -> aggregate)
@footfall/next ───┘                         │        │
  (waitUntil POST /api/ingest)              │        ├─> packages/report -> static report.html   (wedge)
                                            │        └─> golden/accuracy harnesses               (CI)
                                            └─> Tinybird events datasource -> pipes -> apps/web dashboard
                                                             ▲ parity test: pipes ≡ core aggregations
```

## Phase 2: Core analysis engine

**Goal:** the entire value of the product as pure, golden-tested functions. This is the phase where "accurate" is won or lost.
**Estimated effort:** 2–3 weekends.

### Tasks
1. **Normalizers** (`core/normalize/`): Vercel log-drain JSON → Event[]; JSONL passthrough with validation. Each normalizer exports its **field map** (which Event fields it can populate) — this feeds the coverage matrix.
2. **Classifier** (`core/classify/`):
   - Tier 1 — UA-exact table: claude-code, Cursor, PerplexityBot, GPTBot, ClaudeBot, Googlebot, Bingbot, etc. → family + class, confidence `high`. Table is data (`ua-table.ts`), trivially extendable. (UA claims for verifiable operators are IP-verified in **Phase 4.5** — strings can be spoofed; a `Googlebot` UA from a non-Google IP is a spoof, not a crawler.)
   - Tier 2 — browser detection: sec-fetch headers + asset-fetch behavior at session level → `human`.
   - Tier 3 — behavioral agent: no/unknown UA + session features (asset ratio ≈ 0, fetch cadence, markdown `Accept`, conditional-request behavior, path linearity) → `agent`, family `unidentified` (or `codex-suspect` where the signature matches), confidence `medium`.
   - Everything else → `unclassified`. **Never force-assign.**
   - Output per session includes **receipts**: the feature vector, human-readable, exactly as the dashboard mock displays it.
3. **Sessionizer**: per Locked Decisions.
4. **Detectors** (`core/detect/`): `dead_end`, `auth_wall`, `retry_loop` (≥3 same-path hits < 60s), `empty_shell` (200 + html + `resp_bytes` < 3072 + agent session — flagged heuristic; disabled when `resp_bytes` null). Demand signals: 404s on `/llms.txt`, `/llms-full.txt`, `/openapi.json`, `*.md` variants, moved-path clusters.
5. **Recommendations** (`core/recommend.ts`): rule table over detector aggregates → ranked fixes + generated `llms.txt` draft from top agent pages.
6. **Aggregations** (`core/aggregate/`): one function per mock module — traffic split, daily rollup, family breakdown, top pages by agent demand, failure aggregates, coverage matrix. These are THE definitions; the report renders them directly and Tinybird pipes must mirror them (Phase 4 parity).
7. **Accuracy harness** (`scripts/accuracy.ts`): run classifier over `fixtures/traces`, print per-class precision/recall + unclassified rate; write `fixtures/golden/accuracy-baseline.json`.
8. **CI accuracy gate**: fail if Tier-1 precision < 99%, or behavioral (Tier 3) precision/recall regresses > 2 points below the checked-in baseline. (Gate protects against regressions; the baseline itself is a fact, not a target.)
9. Golden tests for every module: fixture input → checked-in expected JSON.

## Phase 4: Live snippet + ingestion

**Goal:** the always-on pipeline: `@footfall/next` → `/api/ingest` → Tinybird, dogfooding on Nitin's own sites. The critical engineering deliverable is **proven fail-open behavior**.
**Estimated effort:** 2 weekends.

### Tasks
1. **`@footfall/next`** (`packages/middleware`): wraps a site's `middleware.ts`. Captures the Event fields, batches, `waitUntil` POST to ingest.
   **Response-visibility constraint (Vercel):** Next middleware runs before the route renders and cannot observe the final response. Therefore the install is middleware **plus server-side status beacons**, correlated by a request ID: middleware stamps `x-footfall-id` on each request and emits the request event; pipeline assumes 200 unless a correction event arrives. 404s: a beacon call in `not-found.tsx` (a **server** component — it renders server-side even for agents). 5xx: `instrumentation.ts` → `onRequestError` (server-side hook). NOT `error.tsx` — that's a client component and would never fire for agents. Assets/API routes have no beacons → status `null`, handled by the coverage matrix. `resp_bytes` stays null on Vercel → the byte-based empty-shell heuristic greys out; instead, a scheduled **outside-in probe** (small cron in `apps/web`) fetches each site's top agent-requested paths agent-style (no JS) and flags shell pages directly. (The future Cloudflare Worker adapter has no such constraint — it proxies and sees full responses.)
   Invariants (each one gets a test):
   - never blocks/modifies/redirects a response
   - hard 500 ms timeout on the send; all failures swallowed after one retry
   - per-site daily cap with graceful sampling above it; **sampled/dropped counts are themselves reported** (no silent truncation)
   - IP hashed with a daily-rotating salt before leaving the middleware; raw IP never serialized
   - config via env vars only (`FOOTFALL_TOKEN`, `FOOTFALL_DISABLED` kill switch)
2. **Ingest endpoint** (`apps/web/app/api/ingest`): token check → zod validation → forward to Tinybird Events API. Edge runtime. Rejects oversized/invalid batches with 4xx (middleware ignores the response either way).
3. **Tinybird**: `events` datasource matching the schema; pipes mirroring every `core/aggregate` function; pipe definitions checked into repo (`tinybird/` dir with `tb` CLI project).
4. **Deploy on own properties**: portfolio + Domino docs. Shadow mode first (capture only, verify data), then leave on.
5. **Fail-open proof** (`scripts/loadtest.ts`, autocannon vs `apps/target` with middleware): three runs — baseline (no middleware), ingest healthy, ingest DOWN, ingest SLOW (2 s injected). Assert Δp99 vs baseline < 10 ms and zero added errors in all cases.
6. **Parity check** (`scripts/parity.ts`): pump a fixture window through core aggregations (TS) and through Tinybird pipes (SQL); assert numerically identical results.

## Phase 4.5: Bot verification & UA-spoof detection

**Goal:** stop trusting user-agent strings blindly. Verify self-declared crawlers/agents (Googlebot, GPTBot, Bingbot, ChatGPT-User, …) against their operators' published IP ranges / forward-confirmed reverse-DNS, so spoofed traffic is caught instead of counted.

**Motivated by a live capture finding (July 2026):** driving real agents at a tunnelled instance of `apps/target`, Claude Code sent `Claude-User (claude-code/2.1.201)` (identifiable), Codex's native tool sent `ChatGPT-User` (identifiable) while its shell path used `curl` (anonymous), and **Cursor impersonated `Googlebot` on ~44% of its fetches** (16 of 36 requests across 5 runs; the rest `curl`/`axios`). UA strings are unreliable and sometimes adversarial; verification is the fix. Without it, spoofed Cursor traffic silently inflates the Googlebot/crawler bucket.

**Estimated effort:** 1 weekend.
**Depends on:** Phase 4 — the middleware/ingest path is where the raw client IP is available (before it is hashed) to perform verification.

### Tasks
1. **Operator table + verifier:** a pure data table (`packages/core/verify/`) of verifiable operators → published IP CIDRs and/or reverse-DNS suffixes (Googlebot → `*.googlebot.com` + Google ranges; Bingbot → `*.search.msn.com`; GPTBot / OAI-SearchBot / ClaudeBot → published ranges). A capture-time verifier maps `(claimed-operator, raw IP) → verified | spoofed | unverifiable` via forward-confirmed reverse-DNS and/or CIDR match. **DNS/network I/O lives at the capture boundary (middleware / normalizer), never in pure `core`.**
2. **Event schema:** add `bot_verified: "verified" | "spoofed" | null` (null when the source can't verify — feeds the coverage matrix). Additive and nullable; handled per the schema-version policy.
3. **Middleware (extends Phase 4):** when a request's UA claims a verifiable operator, verify against cached IP ranges / rDNS at the edge and stamp `bot_verified` **before the IP is hashed**. Fail-open: lookup timeout → `null`, never blocks or delays the response; ranges refreshed on a schedule.
4. **Classifier spoof-guard (extends Phase 2):** a Tier-1 crawler/agent claim is honoured at `high` confidence only when `bot_verified !== "spoofed"`. `spoofed` → drop the claimed family and fall through to behavioural (Tier 3) as `agent` (family `spoofed-crawler`), flagged in receipts. `null` → keep the UA match but mark it "unverified" in the receipt.
5. **Detect + aggregate:** a "spoofed bot traffic" signal — requests claiming a verifiable crawler that failed verification — surfaced in the report/dashboard ("N requests impersonated Googlebot").
6. **Fixtures + accuracy:** verified / spoofed / unverifiable fixtures; the accuracy harness reports spoof-detection precision; receipts display the verification result.

The CLI (`packages/cli`, published to npm as `footfall` so the npx command stays short) executes, in order:
   - **Verify the token against the API first**, echo the site name back ("Site: cli-docs.vercel.app"); on any failure, abort before touching a single file.

   - Create `middleware.ts`, or **codemod-wrap** an existing one (`withFootfall(existing)`). If the codemod can't parse the file confidently, **print exact manual instructions and touch nothing**.

|---|---|---|---|

## Risks & mitigations

- **Behavioral classification is genuinely hard.** Mitigation: precision-first tiers, honest `unclassified`, published accuracy, corpus grows with every misclassification found. Never block a phase on classifier perfection — block on *honesty*.
- **User-agent strings are unreliable and sometimes adversarial.** Observed live (July 2026, real agents at a tunnelled rig): Cursor impersonates `Googlebot` on ~44% of fetches; Codex shells to `curl` (anonymous) though its native tool sends `ChatGPT-User`; only Claude Code self-identifies cleanly (`claude-code/…`). Left unaddressed, spoofed traffic silently inflates the crawler bucket. Mitigation: **Phase 4.5** verifies self-declared crawlers/agents against operator IP ranges / forward-confirmed reverse-DNS and flags spoofs; behavioral classification plus the honest `unidentified` bucket cover the anonymous rest. We name what's verifiable and never fabricate an identity.
- **Vercel log access on free plans is limited.** Mitigation: corpus starts from local capture (P1); real own-site data arrives via the middleware (P4); the wedge accepts middleware-capture as an alternative to uploads. Capture is **forward-only** — no backfill exists on Hobby — so recruit pitches promise "install today, report in 7 days," and capture must be running *before* a fix ships for the fix-impact card to have a before-window.
- **Next middleware cannot see response status/size.** Mitigation (P4): request-ID correlation (`x-footfall-id`) + server-side beacons — `not-found.tsx` for 404, `instrumentation.ts` `onRequestError` for 5xx (never `error.tsx`: client component, invisible to agents); rendered-page-implies-200 convention; outside-in shell probe replaces the byte heuristic on Vercel; coverage matrix greys out anything unavailable rather than guessing.
- **Tinybird free-tier limits.** Mitigation: per-site caps at middleware AND ingest; sampling with visible drop counters; quality script watches quota headroom. If limits bite, sampling tightens — never a surprise bill.
- **Recruiting latency is the long pole for Phase 7.** Mitigation: it starts at Phase 3 (wedge reports need no infra), not after Phase 6.
- **Solo-builder scope creep.** Mitigation: the kill list, the phase gates, and the rule that new ideas get written into `docs/later.md` instead of built.
- **A failure mode to actively avoid:** weakening a verification to make a phase pass. Any gate change must be flagged at the stop and approved.
